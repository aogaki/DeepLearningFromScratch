# フレームワーク本番化ノート — 事件簿と v1.0 要求台帳

このリポジトリは『ゼロから作る Deep Learning』全巻の写経学習用だが、vol3 で作った
自動微分フレームワークは、将来 **別リポジトリの独立ソフトウェア** として作り直し、
研究(核物理 — ΔE-E 粒子識別の事後確率推定、SBI)の本番ツールへ育てる(README のロードマップ参照)。

この文書はそのための **設計仕様の初稿となる台帳**。3 部構成:

1. **持ち越す設計** — vol1〜vol5 で実証済みの型
2. **事件簿** — 実際に踏んだ失敗と、その一般化(同じ過ちを二度踏まないためのリスト)
3. **v1.0 要求リスト+摩擦台帳** — vol5 後半(ステップ 6〜10、PyTorch 写経区間)で
   見つかる摩擦・欠品・意味論差を随時追記していく生きたリスト

運用: 写経中に摩擦が見つかったら、その場で末尾の台帳に追記する(記録者: Claude)。
新リポジトリ着工時に、この文書がそのまま設計レビューの土台になる。

## 1. 持ち越す設計(実証済みの型)

vol3 で確立し、vol4(DQN/方策勾配)・vol5 で実戦済みのもの。新リポジトリの出発点。

- **Variable は `Rc<RefCell<Inner>>` の薄いハンドル**。Python の「全てが共有参照」の明示化。
  リーク検証は Weak 参照の観測テストで。
- **関数の能力を trait で 3 分割**: `Forward`(順伝播のみ・数値微分用)/
  `Function: Forward`(+backward)/ `Creator`(グラフ遡行の最小界面)。
  `call(self)` が self を消費して `Node<F>` としてグラフへ移る —
  「入力未設定」状態が型で存在しない。
- **世代管理つき backward**(トポロジカル順+勾配累積)、`no_grad`/`test_mode` は
  thread_local + RAII ガード(`#[must_use]`)。
- **grad は Variable**(double backprop)。backward 自体が Variable 演算でグラフを作る。
- **broadcast_to / sum_to の双対**、不変条件 `grad.shape == data.shape` を debug_assert。
- **Layer trait**: `params()`(名前なしホットパス)と `named_params()`("l1/W" 階層名)の
  分離。Optimizer は `params()` の Rc ハンドル clone を保持(split-borrow 問題が消滅)。
- **合成スタイル**: dropout・ReLU は「マスク定数 × Mul」で合成 — 手書き backward なし、
  二階微分も自動で正しい。プリミティブを増やすより合成を優先する。
- **随伴ペアの型**(線形演算子): A と Aᵀ を Function ペアにして**互いの backward** にする
  (Im2Col/Col2Im、Concat/SliceAxis、Upsample/UpsampleGrad)。二階が自動で閉じ、
  silent なグラフ切断や `unimplemented!` が構造的に消える。検証はセットで:
  ①手計算値(非対称データ)②内積の随伴検証(Σ gy⊙(Ax) の数値微分 = Aᵀgy)③二階の配線テスト。
- **DataLoader は `IntoIterator for &mut`** で「1 エポック = 1 for ループ」。
  Dataset は関連型 Target(usize 固定にしない)。
- **save/load は npz・2 パス atomic**(全検証後に一括代入 — 部分書き込みなし)。
  キー "l0/W" 形式は Python np.load がそのまま読める(パリティ橋)。
- **f32 で統一**(将来の wgpu / WGSL に f64 が無い)。数値演算は名前付き関数の裏に
  隠しておく(GPU 差し替えの継ぎ目を最初から作る — vol1 の wgpu 経験の教訓)。
- **RNG は常に引数注入**(`&mut impl Rng`、シード固定テストの前提)。乱数系は
  rand + rand_distr に統一(ndarray-rand は使わない — 事件簿参照)。

## 2. 事件簿 — 同じ過ちを二度踏まないために

### 数値(f32)の罠

| 事件 | 一般化 |
| --- | --- |
| EM の負担率崩壊(vol5): 本の f64 前提の初期値で指数部が −200 → `exp` が f32 で 0(f64 なら 1e-87 で生存)、全成分の密度消失 | 尤度・確率は **対数空間で持つ** のが本番の既定。`log_sum_exp` を標準装備。f32 の閾値: exp の引数 ≈ −87 でアンダーフロー |
| EM の対数尤度がプラトーで −4e-4 微減(vol5): 理論は単調非減少のはずが f32 ノイズ(\|LL\| × 相対精度 1e-7)に埋まる | **定理の assert は誤差付き** で。「厳密な ≥」は f32 では成立しない |
| clippy `excessive_precision` 111 連発(vol4 CartPole golden) | f32 の有効桁は約 7 桁。golden 生成は Python 側で `str(np.float32(v))` により最短表記を吐く |
| 数値微分が f32 で有効 2〜3 桁(vol1)、刻みも f64 用の 1e-4 では破綻 | f32 の数値微分は eps = ∛ε ≈ 5e-3、テスト tol は 1e-2 級。gradient check の限界を知る(下記「検証」も参照) |

### 依存関係の罠

| 事件 | 一般化 |
| --- | --- |
| rand 二重化 ×2 回(vol1: 0.9 と 0.10 が並存 / vol5: ndarray-rand 0.16 が rand 0.9 系を引き込み、宣言した 0.10 が未使用に) | 依存を足したら **`cargo tree` で確認** する習慣。乱数は rand + rand_distr に統一し、ndarray-rand は使わない(`random_array` は 5 行で自作できる) |
| ndarray-linalg のリンクエラー(vol5): undefined `_cblas_*` `_dgetrf_` — BLAS/LAPACK バックエンド未指定。C コンパイラは無実 | **外部数値バックエンド依存を持ち込まない**。必要な線形代数(det・inv・Cholesky)は自作済みで移植可能。GPU も wgpu 自前路線で外部依存ゼロを貫く |

### API・設計の罠

| 事件 | 一般化 |
| --- | --- |
| LSTM の `unchain_backward` が dyn 経由で no-op(vol3): 固有メソッドが trait メソッドを陰り、具象呼びだけ動く | trait のデフォルト実装を差し替えるときは必ず `impl Trait for` 側に書き、**`&dyn` 経由の回帰テスト** で封印 |
| silent full BPTT(vol3): truncated BPTT の切断ピンは 2 本(レイヤの h と累積 loss の Add 連鎖)。後者を切り忘れても動くが二次コスト | 「呼び忘れられる規律」は設計で消す。切断は可能な限り **型で不可能** にする(例: Actor-Critic の切断 2 点を f32 境界の計算で表現 — `unchain()` 呼び出し自体が不要になった) |
| `zip` は黙って短い方に合わせる(vol4 DQN の週次同期で顕在化しかけた) | パラメータ列の zip コピーには **長さ assert** を必ず添える |
| 勾配を「切る/運ぶ」の使い分け(vol4): Q 学習はターゲットを `.data()` で切る、方策勾配は π(a\|s) をグラフ付きで運ぶ — 真逆の習慣が同居 | どちらの向きも「**切れていれば optimizer 不動 / 繋がっていれば動く**」の隔離テストで封印できる。フレームワークはこのテストを書きやすい API(パラメータのスナップショット比較)を提供する |

### テスト・検証の罠

| 事件 | 一般化 |
| --- | --- |
| pooling の転置ずれ(vol3): gradient check 全 green のまま値が間違っていた | **gradient check は自己一致検証にすぎない**。縮約・並べ替え系(reshape/transpose/pooling/im2col)は手計算の値テスト必須、かつ **非対称データで**(全同値データは並べ替えに盲目) |
| 2 マス世界の壁 −1 転記漏れ(vol4 GridWorld)・CartPole 物理の写し間違いリスク | 環境・データの転記ミスは自己一致テストで検出不能。**本家を実走した golden とのパリティ** を儀式化(VGG16 1e-4 一致、CartPole 軌道 1e-4、Old Faithful は文献正典値) |
| DQN 初回実験の判定不能(vol4): 単一シードでは「渋いが正常/壊れてる」を区別できず、容量不足がシード運と紛らわしい | 確率的学習は **シード sweep+対照群**。更新則が異なる比較では同一シードでも経験列が分岐するため **ペアドシード比較は不成立**(改善に見えるのは平均への回帰) |
| 「上手くいきすぎると落ちる」assert(vol4 PG): 上限 assert に自分の実験出力が反証 | 下限 = 学習の証明、上限 = 演出。**主張はギャップ assert に一本化** |
| Double DQN が成績で差なし(vol4) | 二次効果(成績)で差が出ないときは **一次量を直接測る**(Q(s₀) の過大評価で 4σ 検出)。物理の流儀がそのまま通用する |
| 本の「図を目視」文化 | **図は統計量 assert に翻訳**(規格化のリーマン和、Φ による真値較正、標本共分散の非対角込み検証、正典値パリティ) |
| `#[should_panic(expected)]` が別のパニックを拾う | panic テストは **パニックする 1 呼び出しに最小化** |
| 9.1→9.2 変質事件(vol4): リファクタ中に可変キャプチャ付き map が畳み込みを飲み込み、アルゴリズムが別物に変質。テストは通り続けた | 可変キャプチャ付き map は畳み込みの隠れ蓑。リファクタ定石 = **抽出 → 全呼び出し移行 → 旧経路削除 → シード固定テストで数字が小数点まで不変なことを証明** |

### Rust 言語・ツールチェーンの罠

| 事件 | 一般化 |
| --- | --- |
| rustc の `unused_assignments` が入れ子 for 内の dead store を見逃す(vol4、最小再現で確認) | lint を過信しない。dead store の検出はリファクタ定石(数字不変の証明)で補う |
| rustdoc で `[修正版]` が intra-doc link 扱いされ警告(vol1) | doc コメント内の半角 `[...]` は避け、全角【】を使う |
| clippy 更新で vol1 に後方警告 47 件が突然出現 | 本番リポジトリは CI でツールチェーンを固定するか、更新追随の運用を明文化する |

## 3. v1.0 要求リスト

### 既知分(vol1〜vol5 前半までで判明)

- **分布装置を一級市民に**: 正規分布(1D/多変量 — Cholesky サンプリング)、カテゴリカル、
  シード注入 API。GMM/EM で使った部品はそのまま要求仕様。
- **log-space ユーティリティ**: `log_sum_exp`、対数尤度 API(EM・VAE の ELBO・拡散の
  共通土台。f32 では対数空間が「任意」ではなく「必須」)。
- **パリティ儀式のツール化**: golden 生成スクリプトの型(`str(np.float32)` 最短表記、
  npz 橋、シード対応表)を新リポジトリの `tools/` に標準装備。
- **wgpu v2 の継ぎ目**: 数値演算を名前付き関数の裏に隠す規約を最初から。
- **CPU 並列の設計余地**(2026-07-30、UNet 学習 703ms/iter を体感したユーザーの要望):
  rayon によるバッチ軸データ並列・im2col/matmul のスレッド化。GPU(wgpu)が本命だが、
  CPU 経路にも並列の継ぎ目を残す。
- Adam は本家準拠の lr_t 畳み込み実装済み(vol3)— そのまま持ち越し。

### vol5 後半で判明する見込みの要求(写経しながら確定させる)

- VAE(ステップ 7): reparameterization trick、KL の閉形式、エンコーダ/デコーダの
  対称構造、BCE 損失
- 拡散(ステップ 8〜10): ノイズスケジューラ、時刻埋め込み、UNet 部品、条件付け

## 摩擦台帳(vol5 ステップ 6〜10 で随時追記)
